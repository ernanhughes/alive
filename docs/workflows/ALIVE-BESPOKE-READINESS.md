# Bespoke Intelligence readiness after PI-02C

This is a dependency report, not an implementation of PI-03 or BESPOKE-01.

1. **Distinct recipes:** WorkflowRunner can execute different immutable DAGs within
   its closed operation registry, owner grant, inquiry, budget and host-lease model.
   The four-stage research review and three-stage source comparison demonstrate
   different graphs through the same engine. General approval gates, arbitrary
   tools and distributed workers are not established capabilities.
2. **Generic inspection:** The observatory consumes definition graph nodes/edges,
   stable stage IDs and attempt records. New recipes need no recipe-specific graph
   component. Output inspection uses bounded structured fields and plain text.
3. **Missing capabilities:** Governed repository inspection, retrieval, scientific
   source ingestion and recipe-specific semantic validation belong to PI-03. No
   operation becomes executable merely because a definition names it.
4. **Selector reference:** A future selector should retain definition ID, name,
   version and canonical hash. A run binds those identities; the viewer checks them
   and refuses contradictory links. Selection is never execution authorization.
5. **Selection rationale:** Retain bounded rationale, considered alternatives,
   selector/policy version and source references in a future governed record. The
   current timeline cannot display rationale that was never stored. No selector
   schema or policy is introduced here.
6. **Explicit authorization:** Existing trusted owner grant events bind exact
   operations, inputs, models, limits and goal/inquiry. The observatory shows safe
   references and budgets, has no write endpoint and issues only authenticated GET.
   A browser deep link carries identifiers, not the grant or bearer credential.
7. **Provenance:** Existing artifact context provenance and evidence IDs remain
   authoritative. Browser/model text is rendered as escaped text, never HTML,
   executable diagram syntax or an automatically followed source URL. Source
   withdrawal status is read from the existing artifact API.
8. **Different validation:** Schema/contract, reference identity, claim semantics
   and independent feedback require distinct contracts. Current reference checks
   do not establish truth. Semantic status remains Unverified where supplied;
   no Intelligence episode, feedback or learning is invented from execution success.
9. **Bespoke versus generic comparison:** Current descriptive run comparison shows
   each version/hash, graph edges, stage state, duration, usage, cost, validation,
   uncertainty and artifact refs. Controlled, independently measured outcome data
   is required to compare quality; cheaper/faster is not a quality score.
10. **Adaptive promotion evidence:** Require independently supplied outcome labels,
    provenance, sampling and evaluation protocol, held-out comparisons, failure and
    uncertainty analysis, consent/budget compliance, reproducible replay and an
    independently approved promotion decision. Existing Intelligence records are
    separate inputs. PI-02C neither initiates learning nor promotes a policy.

Known prerequisites: durable workflow events do not cover every internal transition;
recorded replay discloses that gap. General retrieval/validation tools, broader
execution capabilities and any worker topology need their own qualification.
Claude's R3 review returned GO for the integrated baseline, with two nonblocking
test-strength gaps and an unresolved role-contract watch item retained for follow-up.
PI-02C itself still requires independent review and normal integration.
