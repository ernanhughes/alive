# ALIVE-EVAL-01 — Notebook-02 integration dependency register (superset)

EVAL-01 does not touch production qualification. The narrow migration
specified in R2 (`ALIVE-NOTEBOOK-03A-R2-NOTEBOOK02-DEPS.md`) stands; this
register extends it with the custody-relevant items EVAL-01 needs before
Notebook-03B may consume Notebook-02 contracts.

## Per-source quote status

Versioned per-source requested-quote status; never use the aggregate as
consent or citation proof.

## Integrity precedence

Preserve per-source integrity outcomes; any hash mismatch fails the
affected source; no single enum hides a per-source failure.

## Untrusted title handling

Treat titles as untrusted presentation metadata. Separate presentation
consistency from body/quote validity; titles never enter citation
identity or evidence binding.

## Quote occurrence-unit semantics

Explicit scope and offset units for occurrence counts; no
full-document uniqueness claim from bounded-excerpt counts.

## Historical metric comparisons in CI

Deterministic committed-expectation comparison for the old historical
derived report, in a separate narrow follow-up. The EVAL-01 CI additions
cover only the new custodian paths and must not be read as fixing this gate.

## Single-source and pairwise semantic tasks

Reviewed adapters that resolve owned snapshot/memory IDs server-side,
bind exact serialized evidence plus prompt/schema/model/settings, and
validate structured output and citation checks. Fixture access fields are
experimental conditions, never production authorization proof.

## Governed exact-payload consent

Preview → authorize → analyze binding exact payload/source hashes,
provider/model, token and spend caps, with persisted approvals.

## Budget and provider accounting

Conservative failure charging, cumulative spend caps checked before
dispatch and persisted across restart, provider usage ledgers. No
independent packet-counter instrumentation is claimed where none exists.

## Cancellation and restart qualification

Interrupted-attempt accounting and restart-state semantics for the
adapter paths; previously observed Windows recovery/budget behavior
remains unconfirmed — re-attempt reproduction on Windows with a clean
profile and record the outcome before 03B depends on it.

## Frozen model identity, settings and pricing

Exact supported model/revision/settings, tokenizer and cap semantics,
and verified worst-case pricing frozen under separate owner approval.
The USD 1 ceiling in earlier protocols is a proposal only; authorized
spend remains 0. No inference is authorized by EVAL-01.
