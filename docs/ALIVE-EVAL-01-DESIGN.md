## Why EVAL-01

The R2 audit found a consequential integrity problem: the final verdict
accepted caller-supplied metrics and self-reported custody, so a
rules-only strategy could be declared `PROGRESS` with forged
attestations. R2's public-scope gate already blocks that path in the
shipped CLI, but the underlying decision function trusts whatever it is
handed. EVAL-01 moves the trust boundary: the custodian recomputes
everything from per-case records against custodian-controlled tasks and
gold, and the receipt binds the verdict to its exact inputs.

The core rule: **the model implementer must not supply the final metrics
or decide whether its own evaluation succeeded.**

## Architecture

Three roles with file-access separation (see `ALIVE-EVAL-01-TRUST-MODEL.md`):

- **Implementation author**: submits frozen outputs or a frozen policy.
  Never holds sealed gold.
- **Evaluation custodian**: controls hidden tasks where applicable, gold
  labels, the frozen protocol and scorer; executes scoring; computes the
  verdict from per-case decisions. Only the custodian's recomputation
  counts.
- **Independent annotators/adjudicator**: create and adjudicate gold
  without instruction to match implementation answers.

A label file in the same repository as the implementer is not secret. A
custodian manifest generated by the implementation author is not
independent attestation. Until real independent custody exists the
evaluator reports `CUSTODY_NOT_ESTABLISHED`.

## Custodian evaluator (offline, deterministic)

Inputs: task package, gold package (labels + origins), per-case output
records, custody directory, custodian policy, v1.6 threshold contract,
evaluation request (claimed hashes, requested scope, submitter identity,
optional echoed summary).

The runner: verifies task identity and complete coverage; binds every
output to its exact case (claim refs, exact citations, source hashes —
same ID with changed content fails); rejects missing, duplicate,
substituted, or extra outputs; verifies protocol and scorer fingerprints
against custodian pins; derives family counts from the actual package;
recomputes metrics from per-case decisions with citation/integrity gates;
runs the family bootstrap; applies eligibility then the operative
decision rule; emits a receipt linking the verdict to every input hash.

Submitted summaries are echoed and marked non-authoritative. Scope is
derived from package provenance and custody validity, never from the
caller's flag. An invalid freeze blocks any positive verdict, including
on the direct code path (freeze is re-verified inside evaluation).

## Operative uncertainty

Point estimates no longer suffice: the verdict requires the retention
interval lower bound at/above floor, the misleading interval upper bound
at/below cap, and paired D-vs-C / D-vs-S difference intervals clear of
their margins — otherwise `INCONCLUSIVE`. Degenerate intervals
(identical systems → [0,0]) fail margins rather than passing; imbalanced
families raise a recorded warning; underpowered samples
(< 20 families / < 20 useful / < 30 scored) force `INCONCLUSIVE`.

## Threshold integrity

v1.6 values are frozen and reused unchanged. EVAL-01 adds admission-time
validation: reject NaN/Infinity, non-(0,1) confidence, zero-valued
disablers (precision floor, recall requirement, retention floor,
misleading cap), missing/unknown/contradictory keys, and unused
parameters — each verified by a mutation test that changes a decisive
outcome or blocks evaluation.

## Shortcut and annotation integrity

S (surface-cue-v1.0) and V (shortcut-control-v2.0) are preserved as
development controls and marked honestly: S is template-informed, V is
evaluation-informed. Neither is an independent adjudicator; the final
gate does not rely on the weaker S alone. A procedure for freezing a
genuinely uncontaminated comparator before sealed evaluation is
specified; until one exists that prerequisite stays pending.

The annotation package (v1.7) drops source hashes and access cues,
presents disputed rulings as open adjudication questions, and keeps
handles/salts out of annotator hands. The leakage audit passes the
revised package and fails the R1 package (68 findings) plus tampered
variants. Public cases stay public regardless of renaming.

## Citation

Required-span distribution (20–286 chars, median 72) justifies the 0.2
precision floor as a dump filter: it rejects whole-source dumps
(~0.08–0.11 observed) while tolerating windowed localization. Full
recall is mandatory. What the floor cannot do — relevance, sufficiency,
entailment — is represented explicitly (`entailment:
requires_human_adjudication` on every receipt), never as deterministic
verification.
